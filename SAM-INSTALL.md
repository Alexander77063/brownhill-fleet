# Brownhill Fleet — first-deploy guide

> Public repo: https://github.com/Alexander77063/brownhill-fleet (anonymous clone).
> Detailed operator reference: `HANDOFF-BROWNHILL.md` (in this repo, ~22 KB). Read it if anything here is unclear — push back, don't guess.

## 1. Prerequisites (do these first, before any command on the box)

1. **A Namecheap Business VPS Pulsar** (or any 2 vCPU / 4 GB / 80 GB Ubuntu 24.04 LTS host). 4 GB RAM is sized for "a few dozen vehicles"; resize to 6 GB if the dataset grows.
2. **A registered FQDN** (e.g. `brownhill.example.co.uk`) whose A/AAAA records already point at the Pulsar's public IP. You'll need this for the Let's Encrypt cert.
3. **An email inbox** that Let's Encrypt's terms-of-service mail can land at (e.g. `ops@brownhill.example.co.uk`).
4. **A Backblaze B2 bucket + application key** with list/read/write/delete on that bucket. Recommend a single-bucket setup named e.g. `brownhill-fleet-prod`.
5. **Root SSH access** to the box — every install command runs as root.
6. Standard tools already present on Ubuntu 24.04: `curl`, `psql`, `openssl`, `certbot`, `nginx`, `systemd`. Don't pre-install Docker, your own Postgres, or any monitoring agent — the install assumes a clean Ubuntu 24.04.

You don't need to run the migrations yourself or build the app image — the install scripts do all of that.

## 2. Clone the repo

```bash
sudo mkdir -p /opt/brownhill
sudo chown $USER:$USER /opt/brownhill
cd /opt/brownhill
git clone https://github.com/Alexander77063/brownhill-fleet.git repo
cd repo
```

If your user can't sudo, run `sudo bash -c '...'` for the rest of these commands.

## 3. (Optional but recommended) Pre-fill your secrets

`install.sh` will auto-generate `pg.env`, `jwt.env`, and `bootstrap.env` if absent. It does **not** generate `backup.env` — you must provide your Backblaze B2 credentials.

Create the four files at `/etc/brownhill/secrets/` (mode `0640`) yourself:

```bash
sudo mkdir -p /etc/brownhill/secrets
sudo chmod 0750 /etc/brownhill/secrets

# pg.env — auto-generated by install.sh if absent. 64 hex chars.
echo 'PG_SUPERUSER_PASSWORD=<openssl-rand-hex-32>' | sudo tee /etc/brownhill/secrets/pg.env
sudo chmod 0640 /etc/brownhill/secrets/pg.env

# jwt.env — same value on the Next app and PostgREST. 128 hex chars.
echo 'JWT_SHARED_SECRET=<openssl-rand-hex-64>' | sudo tee /etc/brownhill/secrets/jwt.env
sudo chmod 0640 /etc/brownhill/secrets/jwt.env

# bootstrap.env — used exactly once for the first-run /api/v1/bootstrap call. 64 hex chars.
echo 'BOOTSTRAP_TOKEN=<openssl-rand-hex-32>' | sudo tee /etc/brownhill/secrets/bootstrap.env
sudo chmod 0640 /etc/brownhill/secrets/bootstrap.env

# backup.env — you provide these (not auto-generated).
sudo tee /etc/brownhill/secrets/backup.env > /dev/null <<'EOF'
BACKBLAZE_B2_KEY_ID=<your-b2-key-id>
BACKBLAZE_B2_APPLICATION_KEY=<your-b2-application-key>
BACKBLAZE_B2_BUCKET=brownhill-fleet-prod
BROWNILL_FQDN=brownhill.example.co.uk
EOF
sudo chmod 0640 /etc/brownhill/secrets/backup.env
```

Generate values with `openssl rand -hex 32` (or `-hex 64` for jwt). If you skip this and let `install.sh` generate, **capture the values from the journal before continuing** — they're only printed once.

## 4. Install systemd units, secrets, and PostgREST config

```bash
sudo ./hosted/bootstrap/install.sh
```

This creates `/etc/brownhill/secrets/{pg,jwt,bootstrap}.env` if absent, renders `/etc/brownhill/postgrest.conf`, installs `postgresql.service`, `postgresql.service.d/override.conf`, `brownhill-bootstrap.service`, and `/usr/local/bin/brownhill-bootstrap.sh`, runs `systemctl daemon-reload`, and enables (but does **not** start) the postgresql + brownhill-bootstrap units.

## 5. Fetch the runtime binaries

```bash
sudo ./hosted/scripts/fetch-runtime.sh
```

This installs PostgreSQL 16.4 (via `apt.postgresql.org`), PostgREST 12.2.3 (downloaded tarball, SHA-verified), and Node 22.11.0 (downloaded tarball, SHA-verified) into `/opt/brownhill/`. Versions are pinned in `hosted/scripts/runtime.sha256`.

## 6. Build the Next.js app and stage it for systemd

The systemd unit runs `node /var/lib/brownhill/app/server.js`, so the build output needs to land there.

```bash
# install dependencies + build with the hosted profile
pnpm install --frozen-lockfile
pnpm build:hosted   # = pnpm build:icons && DEPLOYMENT_PROFILE=hosted next build

# stage the standalone output where systemd expects it
sudo mkdir -p /var/lib/brownhill/app
sudo cp -a .next/standalone/. /var/lib/brownhill/app/
sudo mkdir -p /var/lib/brownhill/app/.next
sudo cp -a .next/static /var/lib/brownhill/app/.next/static
sudo cp -a public /var/lib/brownhill/app/public
sudo chown -R brownhill:brownhill /var/lib/brownhill/app
```

If the `brownhill` user doesn't exist yet (it gets created by one of the systemd units on first start), `chown` will warn — re-run it after step 8 if needed.

## 7. Issue the Let's Encrypt cert and bind nginx to your FQDN

```bash
sudo ./hosted/bootstrap/initial-cert.sh brownhill.example.co.uk ops@example.co.uk
```

This runs `certbot --nginx -d <fqdn>`, swaps `brownhill.example.co.uk` → your real FQDN in `hosted/nginx/brownhill.conf`, then `systemctl reload nginx`.

After it returns, verify:

```bash
curl -I https://brownhill.example.co.uk/
```

You should see HTTP 200 and `strict-transport-security` in the headers.

## 8. Apply the schema (one-shot systemd unit)

```bash
sudo systemctl start brownhill-bootstrap.service
sudo journalctl -u brownhill-bootstrap.service --since '1 minute ago' --no-pager
```

The last log line should be `exit 0`. This unit waits for Postgres to answer a query, then applies `standalone/sql/0000_supabase_shim.sql` and every migration under `supabase/migrations/*.sql` in order, then writes `app_state.bootstrap_pending='1'`. **It is safe to re-run.**

## 9. Start the runtime

```bash
sudo systemctl enable --now postgrest
sudo systemctl enable --now brownhill-next
sudo systemctl status postgrest brownhill-next --no-pager
```

Both should show `active (running)`. If they don't, `journalctl -u <service> -n 50`.

## 10. Run the five-gate acceptance

```bash
sudo ./hosted/tests/acceptance.sh
```

All five gates must return OK. Gate 5 (Sunday backup-verify) won't have a run on first deploy — touch the chain once manually to confirm it works:

```bash
sudo systemctl start brownhill-backup.service
sudo systemctl start brownhill-backup-verify.service
sudo journalctl -u brownhill-backup-verify.service --no-pager | tail -10
```

Then re-run `acceptance.sh`; Gate 5 should now report green.

If any gate fails, the script prints the offending output. Don't ship until all five (six, if the accounting module is enabled — check `SELECT count(*) FROM accounting.chart_of_accounts;`) pass.

## 11. Bootstrap the owner account (one-time, only when `app_state.bootstrap_pending='1'`)

From the box (where you have `BOOTSTRAP_TOKEN` available):

```bash
TOKEN=$(sudo cat /etc/brownhill/secrets/bootstrap.env | cut -d= -f2)
NOW=$(date +%s)
BODY='{"email":"you@example.co.uk","password":"a-strong-password-of-12+chars","fullName":"Your Name","businessName":"Brownhill Fleet"}'
SIG=$(printf 'POST/api/v1/bootstrap'"$NOW""$BODY" | openssl dgst -sha256 -hmac "$TOKEN" | awk '{print $2}')

curl -sS -X POST \
  -H "x-bootstrap-t: $NOW" \
  -H "x-bootstrap-sig: $SIG" \
  -H 'content-type: application/json' \
  --data "$BODY" \
  https://brownhill.example.co.uk/api/v1/bootstrap | jq
```

The response is JSON with `access`, `refresh`, and `user.id`. **Subsequent calls return 410 Gone** because `bootstrap_pending` flips to `'0'`.

## 12. Sign in and start using the app

Open `https://brownhill.example.co.uk` in a browser and sign in with the email + password you used in step 11. You'll land in the operator console.

## Ongoing operations

- **Updates** (SSH + git pull): see `HANDOFF-BROWNHILL.md` §5 or `hosted/README.md` "Update (v1)".
- **Backups**: nightly at 02:00 local (`brownhill-backup.service.timer`), weekly verify on Sunday at 04:00. Local retention 7 days, off-host 90 days.
- **Restore**: from the browser, sign in as owner → `/admin/restore`. Pick a dump, type `RESTORE`, submit. Middleware 503s everything except `/admin/*` until the swap completes.
- **Monthly chaos drills**: `hosted/tests/chaos/01-04*.sh`. Log results in `hosted/tests/chaos/RUNS.md`.
